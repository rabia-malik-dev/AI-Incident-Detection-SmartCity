# Practice language & documentation style

## Terminology (project standard)

| Use | Avoid |
|-----|--------|
| **Practice** (explaining concepts, demo prep, portfolio walkthroughs) | “Interview” in docs and assistant prompts |
| **Practice one-liner** / **talking point** | “Interview answer” |
| **Verification** / **test cases** | “Interview prep only” framing |
| **Portfolio** / **employers** / **reviewers** | “Recruiter-grade”, “FANG” (unless quoting external material) |

This project is documented for **learning**, **hands-on practice**, and **demonstrating skills**—not as a cheat sheet for Q&A sessions.

## When working with your AI assistant

In prompts, prefer:

- “Explain for **practice** so I can demo this system.”
- “Give **verification steps** for DB / BE / ML.”
- “**Practice one-liner** for stateless ML + orchestration.”

Avoid: “interview questions”, “what will they ask in interviews” (use “how do I **explain** this in a practice walkthrough”).

2. **2min:** Upload path: Angular (future) → BE → job → ML → SQL → violations.
